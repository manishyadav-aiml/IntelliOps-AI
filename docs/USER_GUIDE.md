# User guide

1. **Register / sign in.** Passwords need 8+ characters with a letter and a digit.
2. **Logs -> upload.** Drop a `.log`, `.txt` or `.csv` file (CSV needs a `message`/`msg`/`log`/`text` column). Status moves PENDING -> PROCESSING -> COMPLETED. FAILED files show the reason and a Retry button. Open a completed file to see top templates, filter entries by level/service/template/text, and inspect any line (original text, parameters, template).
3. **Anomalies.** Pick a completed file and a window (1 or 5 minutes), then *Run anomaly detection*. The result states which method ran (baseline, or a trained model plus baseline safeguard) and how many incidents were created or updated. Re-running is safe: it replaces that file's scores and does not duplicate incidents. Scores are not probabilities. The baseline needs at least 5 earlier windows, so very short files cannot flag anything.
4. **Incidents.** Each episode of anomalous windows is one incident with a rule-based severity and the reasons. Change status (OPEN -> INVESTIGATING -> MITIGATED -> RESOLVED, re-open allowed), severity (recorded with who/when), assign to yourself, add notes and resolution notes. The timeline shows only events that really happened. *Related incidents* are similar past incidents of yours; similarity is not proof of a shared cause.
5. **AI investigation** (needs `GEMINI_API_KEY`). Ask a question or use the default. The answer is labelled AI-generated and unconfirmed, cites evidence ids (hover to see the evidence) and lists limitations. If the AI is unavailable you get a clear message and everything else still works.
6. **Documents + Assistant.** Upload runbooks (PDF/TXT/MD); wait for COMPLETED. Ask questions in the Assistant; the Sources panel shows document, page and chunk for each citation. If your documents don't cover the question you are told so. Without an AI key you still get the relevant excerpts.
7. **Reports.** On an incident, choose PDF, CSV or JSON. AI suggestions and human notes are in separate sections. Past reports are listed under Reports.
8. **Overview.** Metrics and charts come only from your data; empty data shows empty states and `n/a`. Filter by date range, service and hourly/daily buckets.
